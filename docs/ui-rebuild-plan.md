# UI 전면 개편 플랜 (2026-11-19)

목표: 5대 화면(학습하기·오답노트·학습완료·자유훈련·챕터 로드맵)을 React 웹앱으로 만들고, 이후 Capacitor로 iOS/Android 웹뷰에 감싼다.
기술: Vite + React + TypeScript + Tailwind(디자인 토큰은 요청서의 Warm Deep Dark 팔레트). 서버(`apps/server`)는 JSON API + 빌드 결과 정적 서빙.

## 단계와 산출물
| 단계 | 내용 | 완료 기준 |
|---|---|---|
| P1 백엔드 ✅ | 오답 유형 분류, 오답·완료 노트 보강(한글·정답·날짜), 완료 취소(복원), 로드맵 개요 API, 자유훈련(무기록·난이도 필터·성적표) | 단위 테스트 통과 |
| P2 프런트 골격 ✅ | Vite·Tailwind·팔레트 토큰, 3D 버튼, 반응형 내비(상단 탭/하단 탭·키보드 시 숨김), 토스트·모달 | 빌드 성공 |
| P3 학습하기 ✅ | 진행 바·타임어택 게이지·Q 말풍선·좌측 정렬 제시문·textarea·3단 스택·Diff 토글 | 서버 연동 동작 |
| P4 노트·로드맵·자유훈련 ✅ | 오답 상황판, 완료 트로피와 복원, S자 로드맵, 성적표 모달 | 서버 연동 동작 |
| P5 마감 | 모바일 방어(16px·dvh·safe-area·touch-action), 기술 검토 5줄, 커밋·푸시 | 테스트·빌드 통과 |

## 요청서와 데이터가 다른 점(미리 밝힘)
- 오류 유형(패턴/관사·전치사/어휘/시제)은 단어 비교 규칙으로 추정한다. LLM 분류가 아니라서 틀릴 수 있다.
- "패턴 핵심 이해 가이드"는 패턴별 해설 데이터가 없어 패턴 표현과 모범 정답으로 만든 간단한 안내만 넣는다.
- 완료 취소 시 진도는 처음(연속 0)으로 돌아가고 복습 일정은 삭제된다.
- 자유 훈련은 오답노트·진도·통계에 기록하지 않는다(기존 타임어택은 이 방식으로 대체).
- 로드맵은 250개 챕터를 8개씩 페이지로 보여 준다. 잠금 규칙: 처음 미완료 챕터 이후는 잠김.

## 진행 기록
- 2026-11-19: P1~P4 구현(React 화면 5개, 서버 API 5개 추가). P5 모바일 방어·기술 검토(`docs/mobile-packaging-review.md`) 반영. 실기기 확인은 미수행.
- 레이아웃: 요청서의 '좌측 정렬 일직선화'를 따랐다(이전 요청의 '왼쪽 질문/오른쪽 답변 채팅 배치'와 다르다).
- 빌드: `npm run ui:build` 후 서버 재시작하면 `apps/ui/dist`를 서빙한다(없으면 예전 단일 페이지).
- 2026-11-20: TTS 토글(음성 ON 시 질문 재생이 끝나면 타이머 시작, 시간 초과·오류 안전장치 포함), 정답 확인 시 질문→모범 정답 순차 재생, 제한 시간 3배, 2단계 채점(로컬 정규화 → LLM) + 패턴 미카운트 정답(OK_NO_COUNT) + 한 줄 코멘트, 오답노트·학습완료 10개씩 페이지 이동, 첫 화면을 챕터 로드맵으로 변경(학습하기 탭은 숨김).
- 미검증: 실기기 TTS 동작(브라우저별 음성·자동재생 차단), OK_NO_COUNT 판정의 실제 LLM 정확도(단위 테스트는 가짜 판정기로 확인).
- 2026-11-20: 접속 IP 기준 계정(`apps/server/identity.ts`). 이 컴퓨터 직접 접속과 `OWNER_IPS`의 IP는 기존 기록(me), 그 외는 IP 해시 계정. IPv6는 앞 64비트로 묶음. 한계: IP가 바뀌면(휴대폰 데이터망·와이파이 전환) 다른 계정으로 보이고, 같은 공유기를 쓰는 사람은 같은 계정이 된다. 자유훈련 난이도는 A1~C2 전체로 확대.
- 2026-11-20: 소셜 로그인(`apps/server/auth.ts`, `apps/ui/src/Account.tsx`). 제공사 7종(Google·카카오·네이버·GitHub·Discord·Microsoft·Facebook)을 표로 정의하고, `.env`에 키가 있는 제공사만 버튼으로 나온다. 제공사에서 받는 것은 고유 ID뿐이며 해시한 계정 ID(`u-…`)만 쓴다. 로그인하지 않아도 IP 계정으로 쓸 수 있고, "이 기기 전용 계정"(게스트)도 있다.
  - `.env`: `PUBLIC_BASE_URL=https://composition.jwopsworkflowzone.cloud`, `OAUTH_<GOOGLE|KAKAO|NAVER|GITHUB|DISCORD|MICROSOFT|FACEBOOK>_CLIENT_ID` / `_CLIENT_SECRET`(카카오는 시크릿 선택), 기존 기록 연결은 `OWNER_ACCOUNTS=<로그인 후 /api/whoami 의 sessionAccount>`. 세션 비밀은 `data/session-secret`에 자동 생성(또는 `SESSION_SECRET`).
  - 콜백 주소: `https://composition.jwopsworkflowzone.cloud/auth/<제공사>/callback`
  - 검증 범위: 가짜 제공사로 단위 테스트(상태값·PKCE·쿠키 서명·계정 ID)와 임시 서버 동작 확인까지. 실제 제공사 키로 로그인해 본 것은 없다. 제공사별 주소·필드는 문서 기억 기준이라 첫 로그인 때 확인이 필요하다.
- 2026-11-20: 관리자 권한. 관리자 = 이 컴퓨터에서 직접 연 접속, 또는 `OWNER_ACCOUNTS`에 적은 로그인 계정(IP는 공유될 수 있어 근거로 쓰지 않음). 계정 메뉴에 관리자 패널(계정별 시도·정답·완료·마지막 접속, 기록 삭제). 학습 입력 내용은 보여 주지 않는다. API: `/api/admin/users`, `/api/admin/delete?id=`(관리자 외 403).
- 2026-11-20: 로그인 필수(기본 켬, `LOGIN_REQUIRED=0`이면 해제). 로그인하지 않은 방문자는 화면 첫 장에서 로그인 버튼만 보이고 `/api/*`(whoami 제외)는 401. 게스트 생성은 필수 모드에서 403. 이 컴퓨터 직접 접속은 로그인 없이 관리자. 로그인한 계정은 `data/accounts.json`(제공사·시각만)에 남고, 관리자 패널의 "관리자로 지정"으로 `data/admins.json`에 올린다(또는 `OWNER_ACCOUNTS`). Auth.js 프롬프트는 Next.js용이라 쓰지 않고 기존 자체 OAuth 흐름을 유지했다(콜백은 `/auth/<제공사>/callback`).
- 2026-11-20: 계정별 DB와 비로그인 자유훈련. 로그인한 계정마다 `data/users/<계정ID>.sqlite`를 따로 만들고(기존 기록 `me`만 `data/user.sqlite`), 탈퇴(`POST /api/account/delete`)·관리자 삭제 시 그 파일과 로그인 목록·관리자 지정을 지운다. 로그인은 우측 상단 버튼을 눌렀을 때만 시작하고, 비로그인은 모든 메뉴가 보이되 자유훈련만 가능(기록은 메모리에만, 저장 안 함, 다른 API는 401). 이전의 로그인 필수·게스트·IP 계정은 폐지. 구글로 시험 로그인했던 계정이 공유 `data/user.sqlite`에 남겼을 기록은 새 방식에서 쓰이지 않는다.
- 2026-11-20: 관리자 이메일과 원본 콘텐츠 제한. `.env`의 `ADMIN_EMAIL`(쉼표로 여러 개)과 같은 **구글이 검증한** 이메일로 로그인하면 관리자가 되고 기존 기록(`me`)에 연결된다(이메일은 비교에만 쓰고 저장 안 함, 계정 ID만 `data/owners.json`). 이를 위해 구글 로그인이 `openid email` 범위를 요청한다. 원본(구매한 Sentence Kit) 문장은 서버에서 관리자(`me`·이 컴퓨터 직접 접속)에게만 내려가고, 비로그인·일반 로그인은 공개용("own") 트랙만 쓴다. 현재 `own` 트랙 문장은 0개라 일반 사용자는 "공개용 콘텐츠 준비 중" 안내만 보인다. 공개용 문장이 생기면 `apps/ui/src/App.tsx`의 관리자 전용 분기와 `/api/overview`의 관리자 제한을 풀어야 한다.
