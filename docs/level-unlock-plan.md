# 레벨 해금 + 장소 섬 지도 계획 (2026-11-20)

## 1. 확정된 요구
1. 로드맵 = 패턴 학습 + 장소 9개(일상·직장·발표·면접·학교·병원·식당·쇼핑·여행). 챕터는 난이도순 최대 40개.
2. 패턴과 장소가 **같은 패턴 id를 공유**한다. 어느 쪽에서 끝내도 양쪽 모두 완료(진행도는 패턴 id 기준 저장).
3. **사용자 레벨은 하나**다. 어느 로드맵에서든 레벨 L까지 끝내면 *모든* 로드맵의 L 이하 챕터가 열린다.
4. 개요 화면 = 섬 지도(별 배지 + 3분할 고리), 섬을 누르면 챕터 길(같은 시각 언어).

## 2. 규칙 정의 (검토 반영 — 이전 초안의 "첫 미완료 챕터 기준 달성 레벨"은 폐기)
- 레벨 순서: A1<A2<B1<B2<C1<C2, rank 1~6, 0=없음. 화면 3단계: 입문=A1·A2, 중급=B1·B2, 고급=C1·C2.
- 챕터 레벨 = 안의 문장 중 가장 어려운 레벨. 각 로드맵 안에서 챕터는 레벨 오름차순이다(2026-11-20 SQL로 10개 로드맵 모두 역전 0회 확인).
- **사용자 레벨 U**(0~6): 한 번 오르면 내려가지 않는다(저장). U 이하 레벨 챕터는 이미 입증된 것으로 본다.
- **frontier(R)** = R에서 rank > U인 첫 미완료 챕터.
- **proven(R)** = R에 실제 있는 레벨 L 중, U < rank ≤ L인 R의 모든 챕터가 완료된 가장 높은 L. 없으면 U 유지.
  (예: 병원에서 입문을 건너뛰고 B1·B2 챕터만 끝내도 U=B2가 된다. 면접처럼 B1, C2만 있는 로드맵은 B1 완료 시 B1이지 C1이 아니다.)
- **U 갱신**: U = max(저장 U, max proven(R) — 기여 자격 있는 R만). U가 변하지 않을 때까지 반복.
- **기여 자격**: 로드맵 총 **패턴 수**(진행도 저장 단위) ≥ MIN_ITEMS(100). 면접·취업(56)은 제외. ※ 요청에 없던 제 추가 규칙(작은 로드맵 하나로 전체가 열리는 것 방지).
- **열림(open)**: rank ≤ U 이거나 frontier(R). 그 외 잠김. U 이하 챕터는 순서 없이 자유.
- **current(이어하기)** = 열린 미완료 챕터 중 rank ≥ U인 첫 챕터, 없으면 첫 미완료 챕터. 항상 열려 있다(불변식).
- 신규 사용자(U=0)는 기존 "처음 미완료 이후 잠김"과 동일하게 동작한다.
- **상태**: done / current / open / locked. 서버는 잠긴 챕터 `open()` 요청을 거부하지 않고 current로 대체(첫 요청의 오래된 값에 깨지지 않게)하되, 명시 요청이 잠긴 챕터면 403.

## 3. 단계
- P1 팩(ETL, e9/e7): 패턴 문장을 대표 장소에 배치(다수결, 25개 혼합은 1곳). 공유 패턴은 `chapter_pattern`만 추가(pattern·sentence 행 중복 금지). 장소 챕터 = 패턴 + 어휘 문장 난이도순 40개 분할. 팩 0.5.0. 검증: 모든 패턴이 패턴 로드맵 1회 + 장소 1회 등장, 챕터 ≤40.
- P2 앱 로직(domain/app/userdb/contracts): level.ts(순수 함수), overview 상태·userLevel, 최고 레벨 저장, open 잠금 검사, 이어하기 대상, uncomplete 로드맵 인자.
- P3 서버: `/api/overview-all`(로드맵별·단계별 완료/전체·현재 단계·해금 수), 기존 `/api/overview`에 상태 확장. 비관리자 노출 규칙 유지.
- P4 UI: 섬 지도 + 챕터 길(승인된 시안), 레벨업 토스트(localStorage), 모바일/웹 레이아웃.
- P5 테스트·문서·커밋.

## 4. 알려진 한계·결정 필요
- 어휘 카드의 레벨(단어 난이도)과 패턴 레벨(구문 난이도)은 같은 척도로 교정된 값이 아니다 → 해금은 "접근 허용"일 뿐 완료로 간주하지 않는다.
- 사용자가 직접 레벨을 선언하는 배치 테스트는 이번 범위 밖.
- 챕터가 교차 완료로 모두 채워지면 `ChapterCompleted` 이벤트가 나지 않는다(세션 안에서만 발생) — 이벤트에 의존하는 기능이 있는지 P2에서 확인.

## 5. 변경 기록
- 2026-11-24 섬 지도 첫 화면 단순화: 위 1번 4항의 "별 배지 + 3분할 고리"는 **단계 뱃지(입문·중급·고급·완주, 단계별 색) + 진행 고리 1개**로 바뀌었다. 고리와 숫자는 그 섬의 *현재 단계* 기준이며 별 배지·알약·범례는 없다. 해금·잠금 규칙(2번)과 서버 응답(`/api/overview-all`)은 그대로다. 단계별 진행도는 섬을 눌러 들어가는 챕터 길에서 본다. 화면 설계 상세는 `docs/ui-rebuild-plan.md`의 2026-11-24 기록 참조.
